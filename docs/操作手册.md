# 操作手册

面向"要实际操作这个工具"的人。安装/原理见 `README.md`，
字体崩溃的排查过程见 `docs/TMP字体补丁排查经验.md`。

---

## 一、启动

双击 `启动预翻译工具.bat`（或 `python pretranslator.py`）。需要 Python 3.8+。

启动后工具自动做三件事，界面顶部能看到结果：

1. 后台静默拉起 DLX 翻译服务（直连 + 每个代理各一条）
2. 检测直连 / 代理到 DeepL 的连通性，显示出口 IP 与**翻译通道数**；
   配了 API 密钥时会同时显示**本月官方API额度**（已用/上限），超过 80% 会提醒
3. 扫描本机固定盘 + Steam 库，列出识别到的游戏

顶部状态行的「翻译通道: N」很关键——**通道数 = 0 时无法开始翻译**。
去检查代理地址或填一个 DeepL 官方免费 API 密钥。

> **强烈建议配一个官方免费密钥**（deepl.com 注册 API Free，格式 `xxxx:fx`）：
> 实测 20+ 句/秒，是匿名通道的 20 倍左右，且整批 13 个游戏 15,000+ 句零 429。
> 没配密钥且日志频繁 429 时界面会主动提示；跑完每个游戏后额度自动刷新。

## 二、第一次翻译一个游戏

1. 在列表里点选目标游戏（表格里会显示类型：BepInEx / 独立版 / 裸 Unity）
2. 裸 Unity 游戏先点 **安装XUAT(独立版)**
   - Mono：复制过来的 `SetupReiPatcherAndAutoTranslator.exe` 双击跑一次 → 重新扫描
   - IL2CPP：自动下载 BepInEx 6 + XUAT，然后**手动启动一次游戏**（首次黑屏较久属正常），
     正常退出后重新扫描
3. 需要的话调三个开关（都在第 4 行）：

   | 控件 | 什么时候动它 |
   |---|---|
   | 强制重翻(忽略已有) | 换了术语表、或怀疑旧译文质量差时 |
   | 名词术语统一 | 想让人名/专有名词全文一致（默认开） |
   | 缺字修复(TMP图集烘焙) | **中文显示成方框时必须勾**（默认开） |

4. 点 **▶ 开始预翻译**，看进度条。中途可点 **■ 停止**（断点已存，重跑自动续）
5. 完成后点 **▶ 启动游戏** 开玩（游戏列表行也有这个按钮）。它会先自动补齐缺失的
   XUAT 配置（配置缺失时 XUAT 首跑会按默认 `Language=en` 初始化，中文预翻译
   永远不被加载），再像双击一样启动游戏 exe
6. **第一次进游戏没中文？** 依次排查：
   - IL2CPP 游戏（目录有 `GameAssembly.dll`）首跑先生成 interop 组件，正常退出后
     **再启动一次** XUAT 才生效
   - 标题菜单是图片 / 视频内嵌字幕 / Unity Localization 资源表的文字，不在提取
     范围内，这类需游戏自带语言选项解决
   - 还不行按「六、常见问题速查」的"游戏还是日文"一条核对配置

### 2.1 批量预翻译（多个游戏一次跑完）

1. 在列表里按住 Ctrl（逐个点）或 Shift（连选）选中多个游戏
2. 点 **▶▶ 批量预翻译**，按顺序整批跑：
   - 已有**完成标记**（此前完整跑完且校验通过）的游戏自动跳过
   - 每个游戏跑完，列表「状态」列实时显示 ✓ 已完成 / ⚠ 有遗留句 / ✗ 失败
   - 中途 **■ 停止** 随时断，已跑完的保持完成状态，下次接着跑
3. 完成标记写在各游戏翻译目录下（`.pt_done.json`），单个游戏跑完同样会写

**什么情况没有标记？** 该游戏有「永久失败」句或校验不一致。下次批量会重跑它——
断点全命中，只补缺口，不重复消耗额度。永久失败句在状态栏有提示，
**直接再点一次「▶ 开始预翻译」即可只补翻这些遗留句**。

### 2.2 缓存维护

「缓存维护…」列出工具目录 `cache/` 下全部断点缓存目录：

| 状态 | 含义 | 处理 |
|---|---|---|
| 在用 | 对应当前已知的一个游戏 | 不动 |
| 重复 | 同一游戏因历史路径写法不同产生的多份缓存 | 「合并重复项」按句去重合并，不丢句子 |
| 孤儿 | 对应游戏已移动/删除后残留 | 选中后「删除所选」（有确认框） |

### 2.3 运行报告

每次预翻译结束，工具目录 `run_report.jsonl` 追加一行 JSON：时间、游戏、
翻译句数、断点复用数、速度、永久失败数、分通道请求/429统计、写出对数、
校验结果、字体补丁结果、官方API额度消耗。用文本编辑器打开即可复盘。

## 三、字体修复专项

### 3.1 判断需不需要动

- 进游戏后中文变成 `□`/空白 → 需要（勾上复选框重跑即可）
- 中文正常但个别字是"日式写法"（如"説"而不是"说"）→ 这是保底方案在工作，
  说明烘焙没生效，见 3.3
- 游戏**启动就闪退** → 十有八九是旧版动态补丁，见 3.4

### 3.2 换字体

点 **选择字体…**，选一个 `.ttf` / `.ttc` / `.otf`（系统字体在 `C:\Windows\Fonts`）。
不选就自动挑：**雅黑粗体优先**，它的字重最接近日文游戏原图集。

右侧标签会显示当前选择：

- `字体: 自动挑选 (雅黑粗体优先, 贴合原图集字重)`
- `字体: C:\Windows\Fonts\simhei.ttf (手动指定)`

### 3.3 补丁打了但没生效

看日志区（以及 `logs/` 目录）。对照表：

| 日志 | 含义 / 处理 |
|---|---|
| `字体补丁(bake): 缺少 UnityPy` | 装依赖：`pip install UnityPy fonttools numpy pillow scipy` |
| `都没有可烘焙的静态图集, 跳过` | 该 `.assets` 里没有目标，属正常跳过（通常另一个文件里有） |
| `待烘焙字符: 0` | 译文没有超出现有字形，无需处理 |
| `缺字 N 个 (字体不含)` | 选的字体覆盖不全 → 换字体（3.2） |
| `字体烘焙 xx.assets: N 字 (图集 WxH, .resS +M MB) ok` | **成功** |

`numpy` / `pillow` / `scipy` 缺一个都会让烘焙退化成保底方案，
但日志只在导入失败时才提示，装完建议重跑一次确认出现 `ok` 行。

### 3.4 打了补丁启动闪退

旧版"静态图集改动态"路线在部分 Unity 2022.3 游戏上必崩（原生空指针）。
恢复方法：

1. 进游戏 `*_Data` 目录，把 `sharedassets0.assets.bak-PreTranslator` 覆盖回
   `sharedassets0.assets`（`resources.assets` 同理）
2. 确认 `config.json` 里 `"font_patch_mode": "bake"`
3. 重新点 **▶ 开始预翻译**

### 3.5 文字捅出文本框

这是译文比日文原文长导致的排版问题，和字体补丁无关。
打开游戏目录下的 `AutoTranslator/Config.ini`，改：

```ini
ForceSplitTextAfterCharacters=16
```

长句会在 16 字处折行（`0` = 不断行）。数值越小折行越早，
16~20 是比较安全的区间；短标签（≤该字数）不受影响。

## 四、命令行

```bash
python pretranslator.py --nogui scan                     # 列出游戏
python pretranslator.py --nogui check                    # 直连/代理/API/DLX 体检
python pretranslator.py --nogui share                    # 生成脱密分享包

# 完整流水线
python pretranslator.py --nogui translate --game "<游戏根目录>" \
    [--extra-source DIR] [--limit N] [--dry-run] [--redo]

# 只打字体补丁 (不翻译)
python pretranslator.py --nogui fontpatch --game "<游戏根目录>" \
    [--font C:\Windows\Fonts\msyhbd.ttc] [--mode bake|dynamic] [--dry-run]
```

`fontpatch` 的字符集取自**游戏目标语言目录里已经生成好的译文**，
所以典型用法是：先 `translate`（此时会自动顺带打补丁），
发现缺字再单独 `fontpatch --dry-run` 看缺多少 → 换字体重打。

`--dry-run` 只统计不写盘，可以反复跑；真跑是幂等的（每次先从备份还原再烘焙）。

## 五、目录与文件

| 路径 | 说明 |
|---|---|
| `config.json` | 工具配置（GUI 里改的都会存这里） |
| `cache/<游戏名-hash>/` | 翻译断点，删了等于从头翻 |
| `cache/<游戏名-hash>/font_missing.txt` | 译文缺字清单（游戏字体不含的字符） |
| `run_report.jsonl` | 运行报告（每次预翻译一行 JSON） |
| `logs/` | DLX 实例日志 |
| `docs/` | 本手册 + 字体排查经验 |
| `<游戏>/AutoTranslator/Config.ini` | 游戏侧 XUAT 配置（语言、字体覆盖、折行） |
| `<游戏>/*_Data/sharedassets0.assets.bak-PreTranslator` | 字体补丁前的原版备份，**别删** |
| `<游戏>/*_Data/*.resS.origlen` | 图集追加长度记录，删了会导致 `.resS` 重复膨胀 |

## 六、常见问题速查

| 现象 | 处理 |
|---|---|
| 第一次启动没有中文 | IL2CPP 游戏先正常退出**再启动一次**（首跑生成 interop）；配置缺失点「▶ 启动游戏」或重跑一次预翻译即可自动补齐 |
| 标题菜单/视频字幕没翻译 | 标题图片字、FMV 内嵌字幕、Unity Localization 资源表不在提取范围，需游戏自带语言选项（如游戏自带简中表可在游戏内切换） |
| 游戏还是日文 | 看 `BepInEx/config/AutoTranslatorConfig.ini` 里 `Language=zh-CN`、`FromLanguage=ja`；看游戏窗口左上角有没有加载条 |
| 通道数 0 | 代理没开 / API 密钥无效，`--nogui check` 定位 |
| 大量 429 | **配官方免费 API 密钥（实测快 20 倍）**；或多代理多号加通道。日志跑完会给出分通道 429/熔断统计 |
| 额度快用完 | 界面「翻译通道」行显示用量；再注册一个号，逗号分隔填入「API密钥」 |
| 批量某个游戏总被重跑 | 它有永久失败句/校验不一致所以没写完成标记；再点一次「开始预翻译」补翻遗留句；反复出现看日志样例 |
| 状态栏提示"图集不可烘焙" | 该游戏 TMP 图集不是可烘焙的静态图集，已自动走保底（日式写法）；可「选择字体…」指定 TTF 后强制重孋试试 |
| 个别句子始终缺失 | 动态拼接文本，XUAT 查不到，属正常；可把 XUAT 的在线兜底端点打开 |
| 想改某句译文 | 直接编辑游戏 `Translation/zh-CN/` 下对应文件，`ReloadTranslationsOnFileChange=True` 时热生效 |
| 中文是方框 | 勾「缺字修复(TMP图集烘焙)」重跑，见 3.3 |
| 中文是"日式写法" | 烘焙没生效，走了保底，见 3.3 |
| 启动闪退 | 见 3.4 |
| 文字出框 | 见 3.5 |
